---
name: source-index-is-not-source-selection
description: A filing index may accelerate discovery, but current source policy must still select and revalidate the exact bytes.
metadata: { type: gotcha }
---
A first source-index draft repeated packet hashes for every filing and reached
110MB. It also routed a valid Apple reparse by its verification-folder name and
preferred older wrapper-identified parses over fact-identified evidence.

Store one packet record with all filing candidates and one record per structural
file. Route non-ticker directories through the frozen registry only when a unique
fact CIK is present. Record whether every fact carries that identity. The index
never chooses the controlling filing; the existing cutoff/model policy does.
When selected, rehash its files and revalidate identity. Missing copied raw
entrypoints do not invalidate a consumed parsed artifact, but any present
entrypoint must match its declared hash.

Keep cold-build measurement outside the deterministic digest. Copy one compact
index per frozen group, not once per worker. A validated result may be reused only
when input, source-index, policy and implementation hashes all match.

When two fully identified structural records cover the same accession, prefer
the record generated by the current parser definition and carrying complete
filing dates. Lexical path order must not select an older parse merely because
its directory sorts first.
